# Week 2 · 自检问答（RAG 核心链路）

> 面试口述素材。先自己答，再对照。

## Day 6 · 文档解析

**Q1：RAG 第一步"数据接入"要产出什么结构？**

- 统一成 `{text, metadata}` 的 Doc 列表；不同格式差异在这里被抹平
- metadata 至少含 `source`（来源文件）与 `format`；PDF 额外有 `page`
- 后续所有环节（分块、引用、过滤）都依赖这个统一结构

**Q2：为什么 PDF 按"页"存、Markdown 按"文件"存？**

- PDF 天然分页，页是解析的最小可靠单元，且 `page` 元数据支撑"第几页"引用
- Markdown 有标题层级，作为整体保留才能按标题语义分块（Day7 用到）
- 本质：**元数据的粒度由源格式的自然边界决定**

**Q3：PDF 解析的常见坑？**

- 扫描件无文本层 → 需 OCR，pypdf 抽不到
- 多栏排版/表格 → 抽取顺序错乱，需专用解析器（LlamaParse 等）
- 本次用 reportlab 生成、字体嵌入，中文抽取正常

## Day 7 · 分块策略

**Q1：三种策略的差异？**

| 策略 | 特点 | 问题 |
|---|---|---|
| fixed 固定长度 | 按字符硬切，简单可预测 | 切断句子/表格，语义破损 |
| recursive 递归分隔 | 段落→句子→词逐级回退，尽量自然边界 | 重叠可能从词中间切 |
| markdown 标题层级 | 保标题语义，heading 进 metadata | 块长不均（42~721） |

**Q2：`chunk_overlap` 的作用与代价？**

- 作用：防止答案恰好落在块边界，跨块信息被割裂；保证相邻块语义连续
- 代价：存储与 embedding 成本上升（重复内容），检索时可能返回近似重复块
- 经验起点：size 256~512 token，overlap 10~20%

**Q3：为什么字符级重叠有缺陷？**

- 从 `...100 万次` 中间切出 `' 万次'`，产生无意义前缀
- 影响：污染 embedding、干扰关键词匹配
- 改进方向：按 token/句子边界重叠，或先分块再对块整体加权

**Q4：为什么混合检索（Week3）更适合较小分块？**

- BM25 靠词频/逆文档频率：高频词落在**小块**里，相关性信号更集中
- 大块会稀释关键词信号，导致 BM25 打分不准
- 所以 Hybrid RAG 常见起点是 256 token 左右

## Day 8 · Embedding + 向量库

**Q1：向量库存的是哪三样东西？**

- 向量（embedding）：用于相似度检索
- document：原始文本，检索命中后要交给 LLM
- metadata：来源/页码/标题，用于引用与过滤
- 三者由 id 关联

**Q2：BGE 的 query/passage 为什么要区别对待？**

- 检索是**非对称**任务：查询短、段落长，语义分布不同
- BGE 建议查询加指令前缀 `为这个句子生成表示以用于检索相关文章：`，段落不加
- 不加前缀会损失召回；这是 BGE 系列的规范用法

**Q3：余弦距离与相似度关系？**

- 归一化向量后，点积 = 余弦相似度
- Chroma 的 `distance = 1 - similarity`；集合需设 `hnsw:space=cosine`
- 检索按 distance 升序 = similarity 降序

**Q4：为什么段落书写要一致？（实测踩坑）**

- 实测：`企业版每月599` vs 漏写产品名的 `标准版每月299`，结果标准版误排更高
- 原因：长度/格式差异干扰了向量表示，不只是语义
- 结论：同一知识库的块应保持**格式一致**（都带产品名/统一句式）

**Q5：本次检索暴露了哪两个问题？（Day10 深入）**

1. 块粒度：问"企业版多少钱"，#1 命中定价文档但**不是企业版那段**（同文档多主题块相互竞争）
2. 语义假阳性：问"API 速率限制"，#2 混入无关的 AI 训练 FAQ
- 对应解法：混合检索 + Rerank + 更细粒度分块（Week3）
