## 失败模式分类

### FM-1 检索漏召（retrieval miss）
- **案例**：问"私有化版 API 配额"→ 答"未找到"，但答案就在 `04_api_spec.md` 速率限制表（"私有化版 | 由服务器规格决定 | 无"）
- **现象**：`04_api_spec.md` 被检索到（#3），但命中的是认证/端点段，**表格所在块排名不够高**
- **根因**：
  1. 纯向量检索对表格/数字/型号不敏感（语义弱）
  2. 400 字符递归分块把表格行列切散，单块信息不完整
  3. "私有化版"一词在 pricing/integration 也高频出现，分散了向量信号
- **解法（Week3）**：混合检索（BM25 精确匹配"私有化版"）+ Rerank + 更细块（256）

### FM-2 块粒度竞争（same-doc multi-topic）
- **案例**：问"企业版多少钱"，#1 命中的是定价文档里含"标准版"的块，企业版内容靠 LLM 在同块内"顺带"找到
- **风险**：若企业版信息恰好在另一块且未被召回，就会答错
- **根因**：一个 chunk 混了多个主题，检索粒度 ≠ 语义粒度
- **解法**：Markdown 标题分块（Day7 策略3）让"企业版"独立成块；或父子块（小块检索、大块喂 LLM）

### FM-3 语义假阳性（semantic false positive）
- **案例（Day8）**：问"API 速率限制"，#2 混入"AI 训练 FAQ"（都不相关但语义距离近）
- **根因**：向量只看整体语义，缺乏精确匹配兜底
- **解法**：混合检索 + Rerank 重排候选

### FM-4 表格结构化丢失
- **案例**：QPS 表、配额表被压成扁平文本，行列对应关系丢失
- **风险**：多行表格跨块后，模型拼不出"套餐→值"的对应
- **解法**：表格整体成块不切分；或解析阶段转成结构化描述

### FM-5 拒答的两难
- **现状**：本测试 2 个拒答都正确（prompt 起了作用）
- **风险**：过度拒答（明明有答案却说没有，如 FM-1）vs 该拒答却硬答（幻觉）
- **解法**：Week7 用 golden set 量化"拒答准确率"与"幻觉率"，不能只靠感觉

## 结论

项目① MVP 在**事实/列表/聚合**上表现良好，瓶颈集中在**检索侧**：
- 关键词/型号/表格 → 纯向量天然弱
- 块粒度 → 影响召回精度

→ Week3 主攻：**混合检索（BM25+向量）+ Rerank + 分块优化**，直击 FM-1/FM-3。
